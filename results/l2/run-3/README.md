Note on the `failure_cause` of these records. The Gateway answers every 404, including an unknown route, with `{"error": "not_found"}` (`src/ullr_ai/asgi.py`). The attacker's `status_cause` therefore labels the `A13` records `not_found`, although the reason is that the route is not mounted on the agent API: those requests named an action that exists in the session, for which a mounted status route would have answered 200 or 401. The outcome, `blocked`, is unaffected; only the label is imprecise.
